# Qshell SFTP vs Xftp 对比分析与演进规划

> **文档版本**：v1.1.0（2026-10-28 按源码逐项核实修订）
> **对比标杆**：NetSarang Xftp 7 / 8
> **核实范围**：`src/components/layout/sftp-panel.tsx`、`src/components/sftp/*`、`src/store/slices/sftp-slice.ts`、`src/i18n/locales/zh-CN.ts`

> [!NOTE]
> v1.0.0 低估了 Qshell 的现有能力，误将"远程对远程传输、同步浏览、递归权限、目录对比、限速、暂停/续传"列为缺失。本版本已逐项对照源码修正。

---

## 1. 结论概述

Qshell SFTP 在 Xftp 的核心传输能力上**已基本对齐**：服务器间直传（S2S）、同步浏览、递归权限与属主修改、目录对比、传输限速、暂停/续传、中断恢复、失败重试均已实现。

在此基础上，Qshell 还具备 Xftp 没有的能力：与终端一体化、终端路径联动、压缩包免解压预览、远程解压/压缩、内置 Monaco 编辑器、多服务器批量连接、全平台免费与云同步。

**真正的剩余差距**集中在三点：目录对比只做当前层级的差异标色（缺递归扫描与一键同步）、缺少外部编辑器联动回传、缺少 FTP/FTPS 协议。

---

## 2. 功能对比矩阵

### 2.1 已对齐的能力

| 功能点 | Xftp 7/8 | Qshell 现状（已核实） |
| :--- | :---: | :--- |
| **服务器间直传 (FXP/S2S)** | ✅ | ✅ 左右两侧均为远程时走 `s2s` 通道，不经本地落盘；支持对多个右侧会话逐一下发 |
| **同步浏览** | ✅ | ✅ `sftp_sync_browsing`，以当前两侧目录为配对根联动跳转 |
| **权限递归应用** | ✅ | ✅ 权限对话框支持「递归应用」，并支持修改所有者 (chown) |
| **目录对比** | ✅ | ✅ `sftp_compare_directories`，按缺失 / 大小不一致 / 一致对两侧文件标色 |
| **传输限速** | ✅ | ✅ `sftp_rate_limit`，单位 KB/s，0 为不限速 |
| **暂停 / 续传** | ✅ | ✅ 暂停时保留临时文件，可继续传输 |
| **中断恢复** | ✅ | ✅ 「恢复中断传输」批量恢复 |
| **失败重试** | ✅ | ✅ 支持「重试（跳过已完成文件）」 |
| **传输记录列表** | ✅ | ✅ 上传 / 下载 / S2S 分类图标，传输中可暂停 |
| **递归搜索** | ✅ | ✅ `sftp_recursive_search` |
| **路径书签** | ✅ | ✅ 最多 50 个收藏路径 |
| **冲突处理** | ✅ | ✅ 覆盖 / 跳过 / 重命名，含解压冲突处理 |

### 2.2 Qshell 独有优势

| 功能点 | Xftp 7/8 | Qshell |
| :--- | :---: | :--- |
| **终端与 SFTP 一体化** | ❌ 独立软件、独立授权 | ✅ 同一连接，同屏并排 |
| **终端路径联动** | ❌ | ✅ 终端 `cd` 后文件面板自动跟进 |
| **压缩包免解压预览** | ❌ | ✅ 直接查看 `.zip` / `.tar.gz` 内部文件树 |
| **远程解压 / 压缩** | ❌ 需回终端手敲 `tar` | ✅ 右键执行，带进度与冲突提示 |
| **内置编辑器与查看器** | ❌ 调用系统记事本 | ✅ Monaco 编辑器、Markdown 渲染、大日志检索 |
| **多服务器批量连接** | ❌ | ✅ 批量选择、一键连接多台 |
| **跨平台** | ❌ 仅 Windows | ✅ Windows / macOS / Linux |
| **配置云同步** | ❌ | ✅ GitHub / Gitee 端到端加密同步 |

### 2.3 真实剩余差距

| 功能点 | Xftp 7/8 | Qshell 现状 | 影响 |
| :--- | :---: | :--- | :--- |
| **目录对比 → 一键同步** | ✅ 递归比对 + 镜像同步向导 | 🟡 只对比当前层级并标色，需手动选中传输 | 🟡 静态资源发布、配置备份场景需逐层操作 |
| **外部编辑器联动回传** | ✅ 用 VSCode 等打开，保存自动上传 | ❌ 仅内置编辑器 | 🟢 依赖本地 IDE 插件的用户 |
| **FTP / FTPS 协议** | ✅ | ❌ 仅 SFTP | 🟢 老旧 NAS、工业设备等边缘场景 |
| **软链接处理策略** | ✅ 可选跟随或保留链接 | 🟡 可显示链接目标，传输策略不可配置 | 🟢 递归传输时可能遇到循环链接 |

> [!TIP]
> 目录对比判定目前基于文件大小与存在性。若需要更严格的一致性，可在同步向导中增加修改时间或可选的哈希校验。

## 3. 剩余差距说明

### 3.1 目录对比升级为同步向导（建议优先）
* **现状**：开启「对比目录」后，两侧当前目录的文件按缺失 / 大小不一致 / 一致标色，便于肉眼识别差异；但不会递归进入子目录，也不能直接生成同步计划。
* **Xftp 做法**：递归扫描两侧目录树，列出新增、修改、删除清单，用户勾选后执行单向镜像或双向同步。
* **建议实现**：
  1. 复用现有对比判定逻辑，扩展为递归扫描（远程侧注意并发与超时控制）；
  2. 输出差异清单面板（按 新增 / 修改 / 仅目标端存在 分组）；
  3. 一键生成传输任务，复用现有队列、限速与续传机制；
  4. 「仅目标端存在」的删除操作默认不勾选，需二次确认。

### 3.2 外部编辑器联动回传
* **Xftp 做法**：下载到本地临时目录，用系统关联程序打开，后台监听文件修改，保存后自动上传。
* **建议实现**：Rust 后端用文件监听（如 `notify` crate）监控临时文件，变更后经去抖再调用现有上传接口；会话断开或标签关闭时停止监听并清理临时文件。

### 3.3 FTP / FTPS 协议
* 属于边缘需求，建议视用户反馈决定是否投入。若实现，需要在服务器配置、文件面板、传输引擎三层增加协议分支。

### 3.4 软链接传输策略
* 在递归下载 / S2S 设置中增加「跟随软链接 / 保留软链接」选项，并对循环链接做检测。

## 4. 演进路线

```mermaid
flowchart LR
    P0["P0：目录对比 → 同步向导"] --> P1["P1：外部编辑器联动回传"] --> P2["P2：软链接策略 / FTP 协议"]
```

* [ ] **P0 目录同步向导**：递归对比、差异清单、一键生成传输任务。
* [ ] **P1 外部编辑器联动**：用本地程序打开，保存后自动回传。
* [ ] **P2 软链接策略**：跟随 / 保留可选，检测循环链接。
* [ ] **P2 FTP / FTPS**：视需求决定。
