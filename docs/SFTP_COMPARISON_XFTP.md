## 1. 对比背景与定性概述 (Executive Summary)

* **Xftp 7/8 (NetSarang)** 是商业运维领域极具代表性的专业 GUI 文件传输客户端。其核心壁垒在于：**超大文件断点续传的极高鲁棒性、专业的独立后台传输队列控制台（支持暂停/恢复/限速/失败重试）、跨服务器直接对拷（FXP）、目录差异比对与镜像同步、以及调用本地外部编辑器并监听保存自动回传**。
* **Qshell SFTP** 采用了现代化的“一体化运维工作台”设计理念，彻底打破了传统工具终端与传输割裂的痛点，具备**终端与文件面板浑然一体免切软件、终端路径实时联动（Terminal CWD Sync）、压缩包免解压在线透视、一键远程压缩与解压、内置 Monaco 代码编辑器与日志流式检索、全平台免费与云端加密同步**等代际超越优势。
* **演进目标**：在保持一体化与智能化优势的同时，重点攻坚**超大文件断点续传、独立传输队列面板、限速保护、双栏同步导航与本地外部编辑器无缝回传**，使 Qshell SFTP 达到并超越独立商业文件传输工具的专业水准。

## 3. 关键缺失功能深度解析 (Deep Dive: Gap Analysis)

### 3.1 超大文件断点续传（Resume Broken Transfers）—— 🔴 核心痛点
* **业务场景**：日常运维中经常需要上传/下载数 GB 的 Docker 镜像包（`.tar`）、MySQL 数据库全量备份（`.sql.gz`）或系统 ISO 镜像。在弱网、跨国云服务器或网络偶尔抖动断开后，如果必须从 0% 重新传起，体验极为糟糕。
* **Xftp 实现机制**：
  * 当重新发起同名文件传输时，Xftp 会检测远端/本地已有文件的大小；
  * 弹出冲突对话框，核心选项包括：“覆盖”、“跳过”、“**断点续传（Resume）**”；
  * 底层通过 SFTP 协议的 `SSH_FXP_WRITE` 指令指定已存在文件的末尾偏移量（Offset），直接向目标文件追加剩余数据包，从而无缝续传。
* **Qshell 现状与方案**：目前 Qshell 提供覆盖与跳过选项，需在底层传输引擎中引入基于字节偏移量的 Seek 续传机制，并在冲突对话框中增加“断点续传”选项。

---

### 3.2 独立后台传输队列管理控制台（Queue Manager）—— 🟡 批量大杀器
* **业务场景**：在上传几十 GB 的前端静态资源目录或成千上万个小文件时，运维人员需要时刻把控当前整体进度、等待数量、网络速度与失败项。
* **Xftp 实现机制**：
  * 窗口底部常驻可折叠的 **Transfer Queue** 控制面板；
  * 分栏展示：**正在传输（Transferring）、等待中（Waiting）、已完成（Finished）、传输失败（Failed）**；
  * 遇到因网络超时或权限不足失败的文件，会单独归入“失败”列表，用户修正权限后可以点击“一键重试所有失败项（Retry All Failed）”；
  * 允许用户对队列中的任一任务手动“暂停”、“恢复”或“提升传输优先级”。
* **Qshell 现状与方案**：Qshell 底层具备并发控制（`FILE_TRANSFER_CONCURRENCY = 3`），但前端缺乏一个常驻且可操控的全局传输任务抽屉面板。

---

### 3.3 全局与单会话传输限速保护（Bandwidth Throttling）—— 🟡 运维安全
* **业务场景**：在生产环境的单网卡服务器上拉取大文件时，如果不做限速，SFTP 可能会瞬时跑满服务器的上行或下行带宽，直接导致业务 Web 响应超时，甚至引发 SSH 终端严重掉字卡死。
* **Xftp 实现机制**：在选项中提供全局/会话级限速开关，允许设置：
  * **最大上传速率**（如限制为 2048 KB/s）；
  * **最大下载速率**（如限制为 5120 KB/s）；
  * 底层通过令牌桶（Token Bucket）算法平滑流量发送速率。
* **Qshell 现状与方案**：目前为最大全速传输，可考虑在设置与传输面板中增加限速滑动条或输入框。

---

### 3.4 跨服务器直接互传（FXP / Server-to-Server Transfer）—— 🟡 架构级能力
* **业务场景**：从生产机 A 直接将数据同步备份到备份机 B。两台机器都在 IDC 内网或云上 VPC 内，内网千兆带宽极快；若经由运维人员本地弱网中转，传输速度会暴跌且极为耗时。
* **Xftp 实现机制**：在同一个客户端窗口中，左栏加载“服务器 A”，右栏加载“服务器 B”。用户直接在两个远端之间拖拽。如果两台 SSH 服务器支持，可在后台建立双端通道或直接建立两路传输管道，跳过本地磁盘落地。
* **Qshell 现状与方案**：目前左侧固定为“本地系统”，右侧固定为“当前远程系统”，暂不支持双远端服务器对开视图。

---

### 3.5 目录增量比对与镜像同步向导（Synchronize Folders & Diff）—— 🟡 部署提效
* **业务场景**：手动发布静态网站、部署更新包或备份配置文件时，需要比对本地与远端哪些文件发生了变动，避免粗暴全量覆盖耗费时间。
* **Xftp 实现机制**：
  * 提供专门的“文件夹同步（Folder Synchronization）”向导；
  * 自动深度递归比对本地与远程目录的文件大小、修改时间戳；
  * 呈现直观的可视化 Diff 列表（区分出：新增、修改、丢失、冲突）；
  * 用户勾选后，可一键执行“单向镜像（本地覆盖远端）”或“双向同步”。
* **Qshell 现状与方案**：目前需要手动逐层对比和整包拖拽，缺少自动差异探测算法与镜像同步面板。

---

### 3.6 关联本地专业外部编辑器（Open with System/External App）—— 🟢 深度生态联动
* **业务场景**：运维或研发需要修改远程复杂的脚本、配置文件或工程代码，强烈依赖自己本机配置了丰富语法插件、Linter 和格式化工具的本地 VSCode / Sublime Text / Notepad++。
* **Xftp 实现机制**：
  * 右键文件选择“用外部编辑器打开（Open with External Editor）”；
  * Xftp 在后台将远程文件拉取到本地临时缓存目录，并调用系统关联程序唤起 VSCode；
  * **Xftp 主进程在后台对该临时文件进行文件系统监听（File Watcher）**；
  * 开发者在 VSCode 中敲击 `Ctrl+S` 保存的瞬间，Xftp 自动在后台静默将新文件上传回远程服务器，体验极其无感流畅。
* **Qshell 现状与方案**：Qshell 内置了体验极佳的 Monaco Editor，覆盖了 90% 的随手编辑场景；若能增加外部编辑器文件监听静默回传管道，将极大满足高端极客用户的个性化需求。

## 4. Qshell SFTP 相对 Xftp 的代际超越优势 (Superpowers)

在查漏补缺的同时，Qshell SFTP 在一体化与工作流设计上完全领先于 Xftp：

1. **终端与文件管理原生浑然一体**：
   * Xftp 强制与 Xshell 割裂为两款独立软件，授权各自独立，需要打开两个窗口反复切换，经常出现终端连上而 Xftp 掉线的糟糕体验；
   * Qshell 连接后，点击侧边栏或分屏，终端与 SFTP 即可同屏并排展示，登录状态全局打通，一气呵成。
2. **终端当前路径与 SFTP 双向实时联通（Terminal CWD Sync）**：
   * 在 Qshell 终端敲 `cd /var/log/nginx`，SFTP 面板自动探测并跳转至该目录；
   * 在 SFTP 面板中右键某目录，可一键在当前终端快速打开；Xftp 完全无法感知 Xshell 的黑屏敲了什么。
3. **压缩包免解压在线透视预览（Archive Viewer）**：
   * 在 Qshell 中双击 `.tar.gz`、`.zip`、`.tar`，无需下载解压，就能直接在界面透视其内部文件树；Xftp 必须先下载到本地解压后才能看。
4. **一键远程解压与压缩（Remote Extract & Compress）**：
   * Qshell 支持右键压缩包直接在远端触发解压（并带有进度条与覆盖提示），也能一键打包成 tar.gz；Xftp 只能切回终端手敲 `tar -zxvf`。
5. **开箱即用的全套现代富媒体与日志查看器**：
   * 内置 Monaco 代码编辑器（带完整语法高亮）、Markdown 实时渲染面板、大日志流式检索（实时滚屏搜索与关键词高亮）；Xftp 默认只能调用 Windows 原生简陋记事本。
6. **完全免费、全平台跨机云同步**：
   * Xftp 仅支持 Windows，且个人版限制标签页数，商业版价格昂贵；Qshell 全功能免费，且支持 Windows、macOS (Intel/M系列)、Linux，会话还能在 GitHub/Gitee 之间加密同步。

## 5. SFTP 演进路线图规划 (Evolution Roadmap)

为系统性补齐短板并强化专业传输体验，建议分三个阶段稳步落地：

```mermaid
flowchart LR
    P0["阶段一：P0 传输鲁棒性<br/>(大文件断点续传 + 智能重试)"] --> P1["阶段二：P1 批量队列控制<br/>(独立队列抽屉 + 全局限速 + 同步导航)"] --> P2["阶段三：P2 深度生态扩展<br/>(本地外部编辑器联动 + 目录比对同步)"]
```

### 阶段一：P0 级核心鲁棒性（预计周期：1~2 周）
* [ ] **超大文件断点续传（Offset Resume）**：
  * 在底层传输引擎引入基于字节偏移量的 Seek 写入机制；
  * 文件冲突对话框中增加“断点续传”选项，自动检测已有文件大小并继续传输。
* [ ] **传输错误快速重试机制**：
  * 遇到网络抖动断开时，支持一键重试当前任务。

### 阶段二：P1 级批量队列与带宽控制（预计周期：2~3 周）
* [ ] **独立后台传输队列管理面板（Transfer Queue Panel）**：
  * 在 SFTP 底部引入可折叠的传输队列面板，分栏展示传输中、排队中、成功、失败列表；
  * 提供失败项一键重试、手动暂停与继续任务。
* [ ] **全局与单会话传输限速（Bandwidth Throttling）**：
  * 在设置与传输面板中提供上传/下载速度上限滑块，防止跑满服务器带宽。
* [ ] **双栏同步导航联动（Synchronized Browsing）**：
  * 增加同步导航开关，实现本地与远程同名同构目录的联动跳转与回退。

### 阶段三：P2 级深度生态与同步向导（预计周期：3~4 周）
* [ ] **关联外部本地编辑器（VSCode / Notepad++ 监听保存自动回传）**：
  * 增加“用外部程序打开”选项，拉取到缓存目录并调用本地 IDE 打开，通过后台文件监控实现 `Ctrl+S` 静默自动回传。
* [ ] **目录增量差异比对与镜像同步向导（Folder Synchronization）**：
  * 提供本地与远程目录的深度差集比对，生成增量同步预览并一键执行双向同步。
