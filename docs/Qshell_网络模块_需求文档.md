| 项目 | 内容 |

| 文档版本 | v1.0 |

## 1. 背景与问题

现有网络模块是一个**单向的四步流水线**：用户输入域名或 IP 与端口，依次执行 DNS 解析 → Ping → TCP 端口检测 → HTTP 检查，最后给出通过/失败。它能回答"从这个执行点出发，目标现在是否表面可达"，仅此而已。

在真实排障中，这个形态有五个硬伤：

1. **只能回答"通不通"，不能回答"哪一层不通"。** 四步里任何一步失败，用户拿到的只是一个失败标记，看不到是 DNS 解析器配错、路由缺失、ICMP 被安全组丢弃、端口根本没监听、还是 TLS 握手被拒。
2. **完全没有"本机网络视图"。** 用户看不到这台机器的网卡、地址、路由表、DNS 配置、监听端口、活动连接、防火墙计数 —— 而排障时最先要确认的恰恰是这些事实。
3. **没有持续状态。** 接口速率、错误包、丢包、连接数变化都是瞬时快照，缺少时间序列，无法判断"慢"和"偶发丢包"。
4. **结果不可留存。** 每次运行都是一次性的，无法回溯、无法对比"变更前/变更后"、无法作为工单附件交给别人。
5. **深度能力缺位。** 路径追踪（traceroute/MTR）、抓包取证、端口扫描、吞吐测试都没有入口。

市面成熟产品的共识是：**常驻状态 + 按需动作 + 可留存证据** 三者必须打通（Netdata 的常驻遥测、Cockpit 的命令式概览、PingPlotter 的路径时序、Wireshark 的证据链、ThousandEyes 的多点历史）。本模块应沿这条路线升级，而不是继续往流水线里加步骤。

## 2. 目标与非目标

### 2.1 目标

- **G1 看得清**：打开网络页 2 秒内看到这台主机的接口、地址、路由、DNS、监听端口、连接概况与实时流量。
- **G2 定得准**：一键体检能定位到具体失败层（DNS → 路由 → L3 → TCP → TLS → HTTP），并给出候选原因与下一步建议。
- **G3 挖得深**：路径追踪、抓包、扫描等重型能力按需触发，带授权确认、范围约束与资源上限。
- **G4 留得下**：每次运行都是可复现、可对比、可导出的诊断证据包。

### 2.2 非目标（明确不做）

- 不做 Wireshark 级别的协议解析器（抓包产物交给外部 Wireshark 打开即可）。
- 不在目标服务器部署任何 agent / 常驻进程，不引入 eBPF —— 所有服务器侧事实通过已建立的 SSH 会话获取。
- 不替代 Zabbix / Prometheus 做长期时序监控与集中告警。
- 不做无授权的扫描；扫描必须有范围确认与速率限制。
- 不做 Wi-Fi 信号测绘（NetSpot 场景），服务器产品无此需求。
- 不在桌面端默认引入 eBPF / 原始套接字等系统级能力（详见技术文档第 6 章）。
- 不做 7×24 常驻采集与长期基线监控（无 agent 前提下的主动取舍）；实时面板仅在用户打开页面时按需轮询。

## 3. 用户与场景

### 3.1 角色

| 角色 | 关注点 | 主要使用路径 |
|---|---|---|
| SRE / 运维工程师 | 快速定位与复盘、变更验证 | 概览 → 一键体检 → 深度取证 → 导出报告 |
| 后端 / 应用开发 | "我的服务为什么连不上/慢" | 端口占用查询 → 连接查看 → HTTP 分阶段耗时 |
| 交付 / 技术支持 | 新机体检、工单取证 | 网络体检 → 导出 PDF/JSON 附件 |

### 3.2 典型场景

**S1 · 服务访问不通（目标：5 分钟内定位分层）**
用户报告 `api.example.com:443` 不通 → 在目标主机网络页执行一键体检 → 系统给出「TLS 握手失败，对端证书域名不匹配；DNS/TCP 均正常」→ 附证书详情与建议。

**S2 · 端口被占用 / 谁在连**
部署报"端口已占用" → 连接页按端口筛选 → 直接列出占用进程 PID / 进程名 / 命令行 / 监听地址 → 一键跳转到进程模块。

**S3 · 网络慢、间歇性丢包**
概览发现 `eth0` errors/drops 增长 → 接口页看错误细项 → 对目标执行 MTR 持续采样 → 逐跳 RTT/loss 时序图定位劣化起点 → 保存为 incident run。

**S4 · 新机交付 / 上线前体检**
批量选中资产 → 执行"网络体检模板" → 检查接口双工速率、MTU 一致性、路由完整性、DNS 可用性、外网连通性 → 生成待办清单与体检报告。

**S5 · 变更后验证**
安全组/DNS/防火墙变更前后各跑一次同参数 Run → 历史对比视图做 diff → 确认变更生效且无副作用。

## 4. 调研结论（摘要）

完整调研见配套《技术文档》与调研底稿，此处仅保留影响需求取舍的结论：

| 来源类型 | 代表 | 对本模块的关键启示 |
|---|---|---|
| 命令行工具 | `ip -json`、`ss`、`ethtool`、`mtr`、`tcpdump`、`conntrack` | 按「采集成本 + 权限风险」分层，不按知名度选型 |
| 运维平台 | Cockpit、Netdata、1Panel | 指标常驻、动作按需；常驻面板用时间序列，不要每开页面跑一次 `ifconfig` |
| 桌面诊断 | PingPlotter、Wireshark、GlassWire | 路径是时空问题（须保存每轮）；抓包是证据附件；流量要绑定进程上下文 |
| 拨测服务 | ThousandEyes、Catchpoint、Boce、17ce | 同参数才能对比；外部视角只能作为私有资产的补充验证 |
| Rust 生态 | trippy、hickory-dns、socket2、reqwest | Rust 可直接实现 DNS/TCP/HTTP 层；ICMP/抓包下沉到远端命令与 sidecar（不做 agent，不引入 eBPF） |

**一句话结论**：网络模块的产品化对象不是"命令"，而是**主机网络事实**；报告、对比、告警都应从同一套事实模型生成。

## 5. 能力域与功能清单

优先级：**P0 = 首个可用版本必须**；**P1 = 正式版**；**P2 = 后续迭代**。

| A2 | 地址与路由 | 路由表（含 metric/scope/源地址）、默认路由、策略路由规则、到指定目标的选路结果（`route get`） | P0 |
| A3 | DNS 配置 | `/etc/resolv.conf`、systemd-resolved、NetworkManager 三源归一，标注生效解析器与搜索域 | P0 |
| A4 | 邻居与二层 | ARP/ND 表、桥接、VLAN、FDB（容器/虚拟化主机自动展开） | P1 |
| A5 | 防火墙摘要 | iptables/nft 规则计数、DROP/REJECT 命中数、firewalld 区域状态 | P1 |

## 6. 交互设计

### 6.1 信息架构

```
主机详情
└── 网络
    ├── 概览      接口卡片 / 地址 / 路由摘要 / DNS / 监听与连接概况 / 实时速率图 / 最近运行
    ├── 接口      接口详情与错误计数、ethtool 链路信息
    ├── 连接      监听端口 + 活动连接（筛选、聚合、进程跳转）
    ├── 路由与 DNS  路由表、策略路由、邻居、解析器
    ├── 诊断      一键体检 + 高级运行（工具/协议/源接口/次数/超时可调）
    ├── 抓包      过滤器、上限、产物管理
    └── 历史      运行列表、对比、报告导出
```

### 6.2 一键体检（Quick Check）

保留现有四步作为快速入口，但升级为**六层可解释流水线**：

| 层 | 检查内容 | 输出证据 |
|---|---|---|
| L1 DNS | 目标解析、使用解析器、响应码、耗时 | 解析结果列表 |
| L2 路由 | 本机到目标的出接口与下一跳 | `route get` 结果 |
| L3 ICMP | RTT / 丢包（受权限与安全组影响，失败不判定为不可达） | 统计摘要 |
| L4 TCP | 握手结果，区分 refused / timeout / unreachable | 错误分类 |
| L5 TLS | 握手、协议版本、证书链与有效期、域名匹配 | 证书详情 |
| L6 HTTP | 状态码、重定向链、分阶段耗时、响应头 | 瀑布时序 |

**关键规则**：只要不是全通过，就定位**首个失败层**并给出候选原因与下一步动作；不允许只呈现一个总通过率。ICMP 失败但 TCP 成功时，明确提示"ICMP 可能被安全策略丢弃，业务连通性正常"。

### 6.3 高级运行（Advanced Run）

允许选择：目标、协议（ICMP/TCP/UDP/HTTP/HTTPS）、源接口、源端口、探测次数、超时、包大小、过滤器、是否 sudo。所有参数构成不可变的 `RunSpec`，同一 `RunSpec` 的多次运行可直接对比。

### 6.4 实时与报告

- 实时面板：1s/5s 采样，节流 + 页面隐藏暂停 + 失败退避重试，不常驻高频抓包。
- 报告：由统一 `NetworkRun` 模型生成，包含命令、参数、工具版本、权限上下文、原始结构化结果与证据引用；用 `runId` 把图表、表格、日志、pcap 绑定为一个证据包。

## 7. 关键用户流程

**F1 一键体检**：选择主机 → 输入目标与端口 → 点开始 → 六层流水线逐层点亮 → 失败层展开证据 → 一键"保存为 incident run" / "导出报告"。

**F2 端口占用排查**：连接页 → 搜索端口 → 展示占用进程 → 跳转进程详情 / 复制排查命令。

**F3 慢与丢包排查**：概览发现错误计数增长 → 接口页确认错误类型 → 对目标跑 MTR → 时序图定位劣化跳 → 存为基线对比。

**F4 抓包取证**：抓包页选接口与过滤器 → 设定包数/时长/体积上限 → 确认（需 root 能力时提示授权）→ 运行 → 下载 pcap 或用外部 Wireshark 打开。

**F5 变更验证**：变更前跑一次 → 存为 baseline → 变更后用同一 RunSpec 再跑 → 历史页 diff 对比 → 导出结论。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 概览首屏 ≤ 2s（并发采集 + 缓存）；诊断动作启动 ≤ 300ms；万行连接表需虚拟滚动 |
| 资源 | 单次 SSH exec 输出上限 8MB；抓包单文件上限 100MB；单主机并发 exec ≤ 4；采样节流 ≥ 1s |
| 兼容 | 目标主机 CentOS 7+ / Ubuntu 18+ / Debian 10+ / Rocky / Alma / openEuler；工具缺失按能力探测结果降级，不报错中断 |
| 权限 | 默认非特权执行；需要 `CAP_NET_RAW`（ICMP/抓包）或 root 的能力显式标记为"需提权"，经用户确认后执行 |
| 安全 | 命令白名单 + 参数类型化构造；禁止 shell 字符串拼接；目标归属校验；全量审计（资产/用户/原因/时间/参数哈希/证据引用） |
| 可用性 | 错误必须可读且可区分：权限不足 / 工具缺失 / 超时 / 被防火墙丢弃 / 目标不可达 / 解析失败 |
| 可观测 | 每次运行留痕，含工具版本与参数；支持导出为 JSON 复现 |

## 9. 验收标准

1. **视图正确性**：在 CentOS 7、Ubuntu 20/22、Debian 11、Rocky 9、Alpine（无 iproute2 的容器场景）五类环境中，概览/接口/连接三页数据渲染正确或明确降级。
2. **分层定位准确性**：在 6 种注入故障下（DNS 解析失败、无到达路由、安全组丢弃 ICMP、端口未监听、防火墙 DROP、TLS 证书域名不匹配），Quick Check 定位到正确失败层的成功率 100%。
3. **解析健壮性**：每个输出适配器有 golden-file 单测（含空输出、权限不足、版本差异三类异常样本）。
4. **取证可用性**：抓包产物可被 Wireshark 正常打开；报告 JSON 能在同参数下复现同类结果。
5. **安全合规**：参数注入测试用例（含 `;`、`$()`、换行、超长参数）100% 被拦截。
6. **性能达标**：概览首屏与实时面板在 1000 条连接、20 个接口的主机上仍满足第 8 章性能指标。

## 附录 · 术语

| 术语 | 含义 |
|---|---|
| Run | 一次诊断运行，由不可变 `RunSpec` 描述，产出 `Evidence[]` |
| RunSpec | 目标、协议、参数、执行点、权限构成的运行定义，是历史对比的主键 |
| Evidence | 运行产物：结构化指标 / 表格 / 文本日志 / 图表序列 / pcap / 结论注释 |
| Capability | 目标主机上某个工具的可用状态：`available` / `available_with_elevation` / `not_installed` / `unsupported` |
| 执行点 | 本地 Rust 后端 / 已建立的 SSH 会话，二者之一（不做远端 agent） |
