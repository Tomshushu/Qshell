# 历史日志查看功能路线图（Log Viewer Roadmap）

> 维护人：AI Agent ｜ 创建：2026-10-23
> 目标：解决「拉取几天/海量历史日志时，如何快速、精准地定位并查看某一天/某一段日志」的问题。
> 背景结论：海量日志（几百 MB~GB）下，「顺序刷出 + 肉眼盯日期 + Ctrl+C 停」这个交互本质上不可靠——
> 一是 scrollback 容量有限（默认 10000 行）装不下一天日志，二是渲染速度要么快到看不清、要么慢到等不起。
> 因此采用「**先定范围、再拉取**」的分段拉取思路，分三阶段推进。

---

## 一、现状与问题

| 问题 | 说明 |
|---|---|
| scrollback 容量 | 前端 xterm scrollback 默认 10000 行（范围 1000~128000），装不下「一天/几天」的日志（几万~几十万行） |
| 渲染吞吐 | xterm 解析约 50MB/s，海量日志顺序渲染慢；且太快则肉眼无法识别日期、来不及 Ctrl+C |
| 交互 | 现有「`docker logs` 全量拉取 → 刷到某天 Ctrl+C 停」依赖肉眼、不可靠 |
| 来源多样 | 不止容器日志，还有 systemd 服务日志、文件日志、自定义命令日志 |

---

## 二、已完成：第一阶段（命令补全 + 快捷时间）

**目标**：降低「手敲时间参数」的门槛，用户敲 `docker logs` / `journalctl` 时自动提示 `--since`/`--until` 的快捷时间。

**实现**（已完成）：
- `value-completion.ts` 新增 `PARAM_STATIC_VALUES` + `getParamStaticValues`：为 `docker logs --since/--until`、`journalctl --since/--until` 提供快捷时间。
  - docker（Go duration 语法）：`1h` / `6h` / `12h` / `24h` / `72h` / `168h`。
  - journalctl（systemd time 语法）：`today` / `yesterday` / `-1h` / `-24h` / `-7d` / `-30d`。
- `completion-engine.ts` 在动态补全之前插入「参数值静态补全」，优先于容器名补全，修复 `docker logs --since <Tab>` 误弹容器名列表的问题。

**效果**：用户输入 `docker logs --since ` 即看到快捷时间，Tab 选中即可，无需手敲时间戳。

## 三、第二阶段：日志查看器面板（未开始）

**目标**：可视化的「按来源 + 时间范围拉取日志」，结果用带虚拟滚动的专用面板查看，彻底解决 scrollback 容量与「看某一天」的矛盾。

### 3.1 入口
- 终端右键菜单 / 顶部「日志」菜单 / 工作台某处，唤起「查看日志」对话框。
- 上下文感知：默认带入当前服务器。

### 3.2 日志来源抽象（关键：不止容器日志）

| 来源类型 | 识别 | 分段拉取命令 | 时间过滤能力 |
|---|---|---|---|
| 容器 | `docker ps` 列表 | `docker logs --since <T> --until <T> <id>` | ✅ 原生 |
| systemd 服务 | `systemctl list-units` | `journalctl -u <svc> --since <T> --until <T>` | ✅ 原生 |
| 文件日志 | 用户指定路径 | `sed`/`awk` 按行内时间戳切 | ⚠️ 依赖时间戳格式（见第三阶段） |
| 自定义命令 | 用户自定义 | 任意 | 视命令而定 |

### 3.3 时间范围表达
- **相对时间快捷项为主**：最近 1h / 今天 / 昨天 / 最近 7 天（用户通常记不住精确到分钟）。
- **日历点选为辅**：精确到某天。
- 另可做「先拉一小段预览 → 往前/往后翻页」（类似聊天记录「加载更多」），用户完全不用输时间，但需反复执行命令，每次有开销。

### 3.4 查看面板
- **虚拟滚动**：顺畅滚动几十万行，不受 xterm scrollback 限制。
- 支持搜索、关键词过滤、高亮。

### 3.5 待定事项
- 面板是复用现有 xterm 还是新写一个轻量虚拟列表（数据量大时 xterm scrollback 不够）。
- 是否做成「独立弹窗」还是「终端内标签页」。

## 四、第三阶段：文件日志时间戳解析（未开始）

**目标**：让「文件日志」也能按时间范围分段拉取（当前只能对 docker/journalctl 生效，因为它们原生支持 `--since/--until`）。

### 难点
文件日志没有原生时间过滤，需靠 `sed`/`awk` 匹配行首时间戳，而时间戳格式千差万别：
- `2026-10-22 10:00:00`、`2026-10-22T10:00:00Z`、`[22/Oct/2026:10:00:00 +0800]`、epoch 秒/毫秒等。

### 方案（待定）
- 时间戳格式「自动识别」或「手动配置」（按日志来源配置格式）。
- 用 `awk '$1 >= "起" && $1 <= "止"'` 或 `sed -n '/起/,/止/p'` 切分（依赖格式与排序）。
- 若文件无时间戳/格式难识别，降级为「只取最近 N 行」。

## 五、优先级与依赖

1. **第一阶段（已完成）**：命令补全 + 快捷时间 —— 零后端改动，覆盖 docker + journalctl。
2. **第二阶段（下一优先）**：日志查看器面板 —— 完整解决「看历史某一天」，开发量较大。
3. **第三阶段（最后）**：文件日志时间戳解析 —— 脏活，依赖时间戳格式识别，独立排期。
